# 剧本改写指南

## 工作流

1. 调用 `read_episode_script` 读取当前集原始内容。
2. 从用户请求中识别 `normalize`、`short_drama` 或 `dialogue_polish`；没有指定时使用 `normalize`。
3. 调用 `rewrite_to_screenplay`，传入识别出的 `mode` 和本次额外要求。
4. 按工具返回的原始内容和规则完成完整改写，不只返回建议。
5. 调用 `save_script` 保存；如果返回阻断错误，修正后重新保存。

## 规则优先级

原文明确事实、人物关系、关键事件、结局和用户明确要求，高于模式默认规则；模式默认规则高于一般润色偏好。不得为了增强戏剧性新增主线事件、主要角色、关键地点、世界规则或改变结局。

## 三种模式

- `normalize`：保留剧情，整理场景头、动作段落和对白格式，只补足必要的可见动作。
- `short_drama`：为每场戏补清叙事职责、人物目标、阻力、可见行动、方向性变化和退出状态；去掉说明腔和模板句，但不虚构剧情。
- `dialogue_polish`：保持场景事实和动作结构，重点改善对白目的、人物语气、关系压力、潜台词和节奏。

## 短剧改稿原则

- 优先写观众能看到或听到的动作、停顿、距离、物件处理、视线和声音反应。
- 每场戏应有必要的变化：信息、权力、关系、情绪、压力、风险或物理状态至少有一项改变；过渡和后果场不强行制造对手。
- 每句对白服务于争取、回避、试探、施压、确认、转移、威胁、安抚或关系改变，避免重复解释画面。
- 人物语气由身份、处境、关系和节奏区分；没有依据时不强行制造潜台词。
- 不把每场固定 30–60 秒当作字数门槛，按可表演的行动和对白节奏拆场。
- 去掉空泛形容词、总结式金句和重复的“此时/紧接着/与此同时”。

## 当前工作台格式

- 场景头：`## S编号 | 内景/外景 · 地点 | 时间段`
- 动作：自然段，写可表演内容，不写景别、角度、推拉摇移或其他镜头语言。
- 对白：`角色名：（状态/表情）台词内容`。
- 编号从 `S01` 连续递增；兼容旧稿时可以全篇一致使用 `S1`，不得混用。
- 不写视频提示词、`@角色` 引用、资产 ID 或解释性分析。

## 完成前自检

确认没有遗漏原文关键事件，没有擅自改变人物关系和结局；每个场景有正文；场景编号连续；输出只包含剧本。保存工具返回错误时必须修正后再次调用。
